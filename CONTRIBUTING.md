# Руководство по внесению вклада в Cloud Pillow

Спасибо за интерес к нашему проекту! Мы приветствуем вклады от всех членов сообщества.

## 🤝 Как внести вклад

### 1. Форкните репозиторий
```bash
git clone https://github.com/timati1231/cloud-pillow.git
cd cloud-pillow
```

### 2. Создайте новую ветку для вашей функции
```bash
git checkout -b feature/your-feature-name
```

### 3. Внесите свои изменения
- Убедитесь, что код соответствует стилю проекта
- Добавьте комментарии к сложным участкам кода
- Тестируйте ваши изменения

### 4. Сделайте коммит
```bash
git commit -m "Add your commit message"
```

### 5. Создайте Pull Request
- Дайте описание вашим изменениям
- Укажите номер связанной задачи (если есть)
- Убедитесь, что все тесты пройдены

## 📋 Стандарты кода

### JavaScript
- Используйте `const` по умолчанию, `let` для переменных
- Следуйте соглашениям об именовании (camelCase для переменных, PascalCase для классов)
- Добавляйте комментарии для сложной логики
- Максимальная длина строки: 80 символов (где возможно)

### CSS
- Используйте семантические классы
- Форматируйте CSS с отступами (2 пробела)
- Группируйте свойства логически
- Используйте переменные CSS для цветов и значений

### HTML
- Используйте семантический HTML5
- Убедитесь в правильной вложенности элементов
- Добавляйте aria-labels для доступности
- Используйте правильные заголовки (h1, h2, etc.)

## 🐛 Отправка багов

1. Проверьте, не был ли баг уже зарегистрирован
2. Дайте четкое описание проблемы
3. Укажите шаги для воспроизведения
4. Добавьте скриншоты или видео (если применимо)
5. Укажите вашу браузер и операционную систему

## ✨ Предложение функций

1. Используйте название вида: `[Feature] Краткое описание`
2. Объясните проблему, которую это решит
3. Опишите предлагаемое решение
4. Приведите примеры (если применимо)

## 📝 Процесс Pull Request

1. **Название PR**: Используйте формат `[Type] Description`
   - `[Feature]` для новых функций
   - `[Fix]` для исправлений
   - `[Docs]` для документации
   - `[Style]` для изменений стиля

2. **Описание**: Объясните, что и почему вы делаете

3. **Связанные проблемы**: Ссылка на связанные задачи

4. **Чек-лист**:
   - [ ] Я протестировал мои изменения
   - [ ] Я добавил комментарии к коду
   - [ ] Я обновил документацию (если нужно)
   - [ ] Мои изменения не вводят новые ошибки

## 🧪 Тестирование

Перед отправкой PR:
1. Откройте приложение в браузере
2. Протестируйте на мобильных устройствах
3. Проверьте консоль браузера на ошибки
4. Убедитесь, что все фильтры и поиск работают корректно

## 📚 Документация

- Обновляйте README.md при добавлении новых функций
- Добавляйте комментарии к новому коду
- Документируйте сложные функции
- Обновляйте этот файл (CONTRIBUTING.md) при необходимости

## 🎨 Дизайн

При добавлении новых функций, пожалуйста:
- Следуйте существующей цветовой схеме
- Используйте те же шрифты и размеры
- Поддерживайте консистентность с остальным дизайном
- Тестируйте на разных экранах

## 📱 Мобильная оптимизация

Все новые функции дол��ны быть оптимизированы для:
- Смартфонов (320px+)
- Планшетов (768px+)
- Десктопов (1200px+)

## 🔍 Процесс проверки

Один из мейнтейнеров:
1. Проверит код на соответствие стандартам
2. Протестирует функциональность
3. Проверит производительность
4. Оставит комментарии или одобрит PR

## ❓ Вопросы?

- Откройте задачу с названием `[Question]`
- Напишите в обсуждениях проекта
- Свяжитесь с мейнтейнерами

## 📜 Лицензия

Внося вклад, вы соглашаетесь лицензировать свой вклад под той же лицензией MIT, что и проект.
